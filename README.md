# Hear, then Locate · 双板声源定位

**安装 Python 依赖后，双击 `Preview.cmd` 即可预览。** 点「上方」「水平」和「下方」可以检查球面点与右上角的角度是否一致。可以拖动球面，或聚焦球面后用方向键旋转。

先在仓库目录运行 `python -m pip install -r requirements.txt`。建议使用支持 LiteRT 的 64 位 Python 3.13。

## 四人贪吃蛇

运行 `Preview.cmd --game` 进入游戏模拟。点「开始」后，可单独模拟每位玩家拍手，或者点「四人同时拍手」，在慢动作中继续模拟，并用滑块改变各自的响度。实机可运行 `Start-Live.cmd --game`。要玩上下移动，请先在定位页完成俯仰校准，再进入游戏。

- 一个方向拍手，等待约 340 毫秒确认是否还有其他方向，然后朝该方向走。
- 同一短时段内有两个或以上方向，速度降至 0.2 倍。玩家有 1.8 秒继续拍手。每轮最多计四个方向组，参与者应站在不同方向。
- 每组把本轮每一下拍手起声段在阵列处的 RMS 电平取平均。结束时蛇朝平均最高的方向走。最高两组相差不到 0.6 dB 时维持原方向。平均值不随软件显示增益变化。
- 每次起声最多输出一个可信方向。多人的掌声完全重叠时可能合成一个方向。高灵敏度下，较轻而且到达时间一致的突发声也能控制游戏，敲击声偶尔会触发。

## 实机测试

1. 保持原有双板接线，接上两块阵列和 ESP32 的 USB，Windows 连接 Wi‑Fi。关闭占用 ESP32 串口或订阅其音频的其他脚本。
2. **双击 `Start-Live.cmd`**。浏览器会自动打开。脚本通过串口启动现有 ESP32 程序，并接收它发出的双板 UDP 音频。展开「采集详情」可查看生效的板间距。终端按 **Ctrl+C** 可以停止。
3. 等上板和下板都显示在线，先安静约一秒，让界面测背景声。把声源放在**两板中间高度**，点击「校准俯仰零点」，保持位置发声约 5 秒。也可以用手机播放连续说话声或宽带噪声。
4. 校准成功后，先在 USB‑C 正前方的中间高度发声，应接近方位角 0°、俯仰角 0°。再用同一个声源分别试上方和下方，每个位置持续发声约一秒。方位角俯视顺时针，俯仰角上方为正，下方为负。声源在接近正上或正下时，界面只显示俯仰角。

校准前仍会估算水平方位，俯仰角显示为「—」。校准值跟随本次采集，重启后重新校准。球面始终使用单位半径，点表示方向。采集过程中只保留最近的窗口用于计算。

界面以背景声为参考检测持续发声，并降低接近背景频谱的成分在定位中的权重。三个窗口的方向相近后才显示角度，停止发声后短时间内清除读数。

## 拍手和响度

- 实机球面用彩色编号标出约 340 毫秒内独立起声的不同拍手方向，最多四个。每次起声最多一个点。右侧有同色编号及对应角度。标记保留约 1.6 秒；校准前显示在赤道上，俯仰角留空。
- 程序同时检查双板的全频和中频突发声。高灵敏度会先提示「检测到短促声」，用起声段尝试定位。随后，本机的 [YAMNet](https://www.tensorflow.org/lite/examples/audio_classification/overview) 可以把提示更新为「检测到拍手」，并计入已确认次数。单次声音若只符合时频特征，标为「疑似拍手」。方向证据不足时会显示「方向不稳」。高灵敏度也可能把键盘声等短促声音标记为候选。
- 响度条旁显示计入软件增益的数字电平（dBFS），下方显示原始电平和相对背景声的差值。dBFS 以数字满幅为参考，不能直接换算成声压或距离。
- 展开「声音设置」。选「检测灵敏度 → 高」可尝试检测较弱的声音，但可能增加误报。「电平软件增益」可选 0 / +6 / +12 dB，只改变电平表显示。当前原始麦克风输出绕过 XVF3800 的板载数字增益。
- 拍手分类使用随包提供的 Google YAMNet TFLite 模型，许可证见 `LICENSE-yamnet.txt`。测试样本来自 [ESC-50](https://github.com/karolpiczak/ESC-50)，测试音频未随包分发。

## Wi-Fi 音频传输

实机页的 **Audio settings → Wi-Fi audio format（声音设置 → Wi-Fi 音频格式）** 可以切换 ESP32 的发送格式。两档都保留每路 16 kHz 的八路同步音频。USB 串口负责启动与配置，音频经 Wi-Fi UDP 到达电脑。

| 格式 | ESP32 发送内容 | 双板合计带宽 |
| --- | --- | --- |
| 低带宽 16 位（支持时默认） | 去除空时隙，每块数据用共享指数编码成有符号 16 位样本，通常三个数据块合并发送 | 满块时约 2.32 Mbps，约 250 包/秒 |
| 原始无损 | 完整保留 32 位 I²S 时隙，逐包使用无损变长编码或原始字 | 随声音变化，未压缩满块约 6.50 Mbps，约 750 包/秒 |

表中带宽包含应用、UDP 和 IPv4 包头。页面显示电脑实际收到的速率。旧固件仍可使用原始档，支持新协议时才能切换。定位采样率和方向校准在切换时保持一致。试听播放器输出 16 kHz 单声道 PCM16 WAV。

## 语音触发和降噪

在实机页选「语音 · Snake」，说 **Snake** 或 **Hey Snake** 后停一下。识别成功会更新计数，方位稳定时在球面显示彩色点。关闭「背景降噪」可以用同一位置对比。开启时定位会降低持续背景频率的权重，识别会在方向稳定时对齐一块板的四路音频，再压制学习到的稳定背景声。响度表仍读取原始电平。说话音频只在本机内存处理。

说完后点「抓取最近 4 秒」，用「听原始」和「听降噪」比较同一段阵列收音。两个版本使用相同试听增益。缺失的音频段会显示时长并填成静音。页面上的语音计数同时列出匹配口令次数和送去识别的片段数。

要启用语音，先运行 `python -m pip install vosk==0.3.45`。从 [Vosk 模型页](https://alphacephei.com/vosk/models) 下载 `vosk-model-small-en-us-0.15`，解压到 `models/`，也可在启动时用 `--speech-model` 指定解压后的文件夹。模型未安装时照常使用拍手模式。

要补查短句中的 Snake，可再安装 `sherpa-onnx==2.0.3`，从 [关键词模型页](https://k2-fsa.github.io/sherpa/onnx/kws/pretrained_models/) 下载英文 `sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01`，解压到 `models/` 或通过 `--keyword-model` 指定目录。Vosk 会先排查容易混淆的词，关键词模型在本机处理剩余片段。

## 阵列设置

`array.json` 的板间距设为 **6.0 cm**，对应上下两层麦克风平面的垂直距离。默认麦克风方阵边长 66.6 mm，两板同向朝上、USB‑C 对齐。通道配置的每项是一个 0 起始的音频通道编号，从 USB‑C 一侧沿俯视顺时针列出四个位置。默认顺序需要结合实物测试确认。修改后重新启动。

角度使用 GCC‑PHAT 给球面候选方向打分，搜索网格的步长为 3°。实机角度误差由现场测试确定。零点校准前使用两板各自的板内麦克风对，校准后加入 16 对跨板麦克风，共 28 对。两块板只在共同连续、打包标记通过的窗口中联合计算。如果两板的麦克风无法在垂直方向一一对应，当前中间高度校准方法需要调整。

## 命令行

```powershell
python app.py
python app.py --live --serial COM14
python app.py --live --host "ESP32_IP_ADDRESS"
```

`--host` 用于已经连上 Wi‑Fi 并启动采集的 ESP32。把 `ESP32_IP_ADDRESS` 换成设备的实际地址。`--serial` 可指定 Windows 设备管理器中 ESP32 的端口。界面只在 localhost 提供服务。球面的上下两层网格和赤道分界参考了 [ODAS Studio](https://github.com/introlab/odas_web/blob/master/resources/js/source_sphere.js)。
